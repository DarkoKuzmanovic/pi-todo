## Outcome

`pi-todo` alone provides the current `oh-my-todo` user-facing polish while preserving the existing explicit task tools and `/todos` viewer.

## User-visible / operational value

After M0, the active Pi setup can rely on one todo extension for task tools, prompt injection, full-screen viewer, compact above-editor widget, slash helpers, and completion notifications.

## Scope

### In

- Port `TaskTracker` behavior into `pi-todo` with deterministic Vitest coverage.
- Port compact above-editor widget rendering under a `pi-todo` widget key.
- Integrate tracker refresh, compact widget updates, and celebrations into `src/index.ts` lifecycle/tool-result handling.
- Move `/done`, `/start`, `/next`, and `/pause` helper commands into `pi-todo` while preserving auditability through `todo_write` instructions.
- Update README/changelog for merged behavior.
- Verify merged behavior before disabling standalone `oh-my-todo`.

### Out

- Dependency metadata, tombstones, and rich task fields; these are later milestones.
- Permanent deletion of the old `oh-my-todo` folder.
- Replacing the explicit tool API.

## Acceptance criteria

- `pi-todo` alone provides all current `oh-my-todo` user-facing behavior.
- Existing `todo_write`, `todo_read`, and `todo_remove` tools keep the same names and schemas.
- `/todos` continues to open the full-screen task viewer.
- `/done`, `/start`, `/next`, and `/pause` are registered by `pi-todo`.
- Above-editor compact widget is owned by `pi-todo`, not `oh-my-todo`.
- Vitest passes in `pi-todo`.
- Manual reload/trial workflow verifies task creation, compact widget, helper commands, and full-screen viewer before `oh-my-todo` is disabled.
