## Goal

Add optional rich task fields to `pi-todo` (`description`, `owner`, `metadata`, `activeForm`) so tasks can carry richer context (long-form notes, agent/user attribution, free-form key-value, in-progress label) without breaking backward compatibility, the M1 replay/snapshot invariants, the M2 dependency metadata, or the M3 tombstone model.

## User-visible / operational value

Agents and humans can encode richer task context — long-form notes in `/todos`, agent/user attribution, an in-progress `activeForm` label that replaces the static task label in the prompt — without paying a per-turn prompt cost for the hidden fields. After M4, the prompt block carries `activeForm` (active-task label) for situational awareness; `/todos` and the compact widget carry `description` for reference; metadata is preserved in canonical state and replay for future surfacing without changing the current UX. The visibility map is tighter than the M2/M3 baseline and explicitly protects prompt budget.

## Scope

### In

- Extend stored `Task` type and `TaskDetails` with optional `description?: string`, `owner?: string`, `metadata?: Record<string, string|number|boolean>`, `activeForm?: string` (additive optional; M-a confirmed M2 pattern, not M3 stored-only).
- Extend `TaskSchema`/`TodoWriteParams` TypeBox schemas with the same 4 fields (additive optional, M2-style authorable; per P0-b preserve the public tool surface).
- Update `extractTasks()` in `src/tracker.ts` to faithfully extract all 4 fields with safe coercion (sibling-consistent: e.g. `description: typeof t.description === "string" ? t.description : undefined`).
- Update compaction snapshot payloads (`pi-todo:snapshot` custom entry) to carry the 4 new fields.
- **B1 — Metadata replay safety:** Replay extraction must (a) preserve value *types* (test `typeof`/strict-equal per key — `1` ≠ `"1"` ≠ `true`), and (b) defensively re-validate flatness on history (malformed historical entries must not crash replay; drop invalid keys with the same per-key policy as input, otherwise replay diverges from a fresh `todo_write`). Hard blocker because the watch list flagged replay/persistence as invariant-sensitive.
- **I1 — Metadata validation policy:** Per-key reject-with-named-warning. Invalid metadata values (nested objects, arrays, null) are dropped per key with a specific warning naming the key (e.g. `metadata.foo dropped: nested objects not allowed`); valid keys survive. Whole-task rejection only if the `metadata` *container* itself is malformed (not an object).

  - `activeForm`: prompt (active-task label) + `/todos` list (escaped prompt-side per I3)

## Phase boundary health

M4 is coherent as a standalone milestone because rich fields are additive optional metadata that strengthen the existing task model without requiring priority/dueAt semantics, M3's reveal toggle, or M5's archival. After M4, projects that never use the 4 new fields behave identically to M3; projects that do use them gain richer task context with the M-c visibility discipline actively protecting prompt budget (description stays in reference surfaces; `activeForm` is short, bounded, and the only user-authored text in the prompt). M2/M3 invariants (single replay source, faithful `extractTasks`, M3-todo_write tombstone preservation, defensive B1 metadata handling) remain intact.

## Constraints / invariants

- **Backward compatibility:** omission = no rich field; old payloads valid.
- **Single replay invariant:** rich fields flow through the same shared `extractTasks` boundary; no normalization at replay.
- **B1 — Metadata type safety:** replay preserves types; defensive flatness re-validation on history; never crash on a malformed historical entry.
- **I1 — Input-boundary validation:** per-key reject-with-named-warning for invalid metadata; whole-task reject only for malformed container.
- **I2 — Resurrection authoritative:** rich fields on a resurrected task come from the new payload (no M3-style merge-back from the audit-retained pre-tombstone payload).
- **I3 — Prompt safety:** any user-authored text in the prompt block (currently `activeForm`) is rendered in a delimited data region with structural-delimiter escaping; one explicit test feeds a delimiter-containing string.
- **M-d — `isBlocked` ignores rich fields:** blocking is purely a `blockedBy`-graph + tombstone concern; rich fields never affect block state.
- **M-b — Malformed-clear symmetry:** clearing a task on malformed replay must also clear rich fields (no orphan state).
- **No silent mutation:** rich fields come through explicit `todo_write`; helper commands continue to recommend actions and route mutations through the public tools.
- **Prompt budget discipline:** description stays in reference surfaces (not prompt); `activeForm` is short and bounded; metadata hidden.
- **M2/M3 independence:** `blockedBy` semantics and `deletedAt` semantics unchanged; a tombstoned task retains rich fields for audit; resurrection clears `deletedAt` and applies the new rich fields authoritatively.
- **Continuous cadence hardening (I4, non-negotiable):** orchestrator-side full-suite `npm test` at every T-boundary, "never report success while the suite is red" rule, dropped-import/unused-symbol check, orchestrator gates at T1→T2 and T3→T4 minimum.
