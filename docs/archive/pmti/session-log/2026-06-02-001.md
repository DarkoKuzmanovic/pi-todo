## Reviewer verdict (2026-06-02 23:04) — REJECT

First REJECT in the PMTI comparative-trial set (M1/M2/M3 all `Approve with amendments` or `Approve`). 1 critical + 2 important + 4 minor findings with 345/345 tests passing and biome/tsc clean but a real spec violation in the I1 input-boundary policy.

- **Critical I1 — malformed metadata container is warning-only in `todo_write`, not a whole-task rejection:** `validateMetadata()` correctly returns `{ok:false, error}` for non-object containers (`src/rich-fields.ts:65-70`), but `src/index.ts:170-175` only pushes `mdCheck.error` into `richWarnings` and proceeds to store the task at `src/index.ts:201-215`. As a result, `metadata: "not-an-object"` becomes a successful write with metadata silently omitted plus warning, violating `.pi/pmti/milestones/M4.md:28` and `README.md:72`.
- **Important M3 leak — `/start` blocked follow-up:** `src/commands.ts:111-112` interpolates raw `task.blockedBy?.join(", ")` into the follow-up message, so a live task blocked by a live dep + a tombstoned dep includes the dead ID in the follow-up, regressing M3's "dead id never printed" invariant. The `notify()` call above uses tombstone-aware `blockedByContext()` but the `sendCommand()` does not. Fix: use `activeBlockerIds()` / `blockedByContext()` instead of raw `task.blockedBy`.
- **Important I3 — delimiter escaping in `renderActiveFormForPrompt()`:** `src/prompt.ts:40-45` wraps the value in a single-backtick code-span and "escapes" embedded backticks with backslash, but the test at `src/prompt.test.ts:26-39` explicitly accepts four backticks in the output, meaning inner delimiter characters remain in the rendered data region.
- **Minor M-f /start//next activeForm surfacing absent:** helper messages use `task.content` / `active.content` / `nextUp.content` only at `src/commands.ts:111-115` and `src/commands.ts:139-147`.
- **Minor I2 tombstone-rich-fields test covers only 3 surfaces (activeTasks, formatListForLLM, TodoViewComponent) at `src/symmetry.test.ts:642-689`**, not the requested 5-surface assertion.
